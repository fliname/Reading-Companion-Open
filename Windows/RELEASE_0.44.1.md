# Windows 0.44.1 · 同步 Mac 0.55.4 阅读修复

2026-09-06。适用于 Windows 10/11 x64，沿用原有书架及项目数据目录。

## 本次同步

- EPUB、AZW3、MOBI 拖选立即显示淡蓝色；按住鼠标移到右侧边缘会自动翻页继续选择，跨章节选区也会保存。确认划线颜色后才改色。
- 虚构类保存人物管理时保留阅读位置；人物高亮不再通过修改正文节点引起重新分页。
- 电子书和 PDF 锁定时固定阅读区及两侧栏宽度，锁定期间不能拖动分栏、缩放或切换单双页。
- 右下角书名使用文件名（去掉最后一个扩展名），保留中文和空格；其他位置的图书元数据标题不变。
- 人物批量输入支持 `人物名字/别名/另一个别名：信息`，也支持全角斜杠。别名可省略，会去除重复名字。
- PDF 锁定记录当前可见页面的归一化横纵范围；翻页时复用上下裁切位置、比例及缩放范围。
- 书架文件夹旁增加“删除”按钮。删除文件夹只移除文件夹及成员关系，书籍仍留在书架。
- PDF 顶栏增加单页/双页切换；双页按 1–2、3–4 配对并每次翻两页，底栏显示对应页码范围。
- PDF 划线绘制高度缩至原文字框约 70%；同一行相邻 OCR 片段合并为平整色块，减少中间断色并避免上下行重叠。
- 打开书架中的书会恢复上次位置。PDF 等待渲染器初始化后恢复；电子书保存章节、文字偏移及当前排版参数。关闭窗口前会等待保存进度。
- 虚构类概要的页码标题及正文均可点击，跳回对应原文。电子书的概要、生成范围和目录使用文字锚点，在字号、单双页或窗口尺寸改变后更新显示页码。
- 修复 PDF.js 6 下重新打开 PDF 时的旧文档释放接口，避免打开流程中断。

## 数据兼容

新生成的电子书概要保存正文锚点。旧 Windows 版只有页码的概要会在首次打开时按当前排版补建锚点；若旧概要生成时的排版已经改变，请核对一次原文范围。仅有旧页码的阅读进度也按当前排版迁移，之后保存精确文字位置。

## 验证

- 59 项 Node 自动化测试通过，包含原有 EPUB 导入、PDF/OCR、目录、检索、Obsidian、人物及书架测试，以及新增裁切比例和 OCR 高亮几何测试。
- 在 macOS 上使用 Chromium 运行 Windows 版真实渲染代码，模拟 Electron 文件和项目接口：跨页鼠标拖选、淡蓝预览及确认改色、人物保存、分栏锁定、概要跳转和动态页码、目录重排、PDF 双页翻页、裁切恢复、两种格式重新打开和文件夹删除。
- 这里没有运行 Windows 真机。安装/卸载、Windows 字体和缩放、系统语音、DPAPI、无 DRM 的 MOBI/AZW3 转换以及实际书籍 OCR 效果仍需 Windows 10/11 验收。

## 开发复现

`node --test tests/*.test.cjs` 运行单元测试。

`node scripts/sync-mac-reflow.cjs` 从同仓库 Mac 的 `ReflowReaderHTML.swift` 重新生成共享正文模板，Windows 消息桥接在脚本中维护。

交互测试使用 `node scripts/verify-reader-ui.cjs`，可通过 `PLAYWRIGHT_MODULE` 和 `CHROME_PATH` 指定本机 Playwright 模块和 Chromium 路径。测试只使用自建样本和模拟书架，不连接 AI，也不访问个人书架。
