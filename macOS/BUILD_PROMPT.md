# Reading Companion - 实施提示词

你是一名资深 macOS 原生应用工程师、PDF/OCR 工程师和 AI 阅读产品设计师。请在当前空工作区从零实现一个名为 **Reading Companion** 的 macOS 原生应用。

## 目标

构建一个把 PDF 阅读、`ljg-read` 式可追溯 AI 伴读和 Obsidian 笔记整合在一起的工具。优先保证用户能打开一份 PDF，可靠阅读、划线、提问并把结果无损写入 Obsidian；不要把它做成只会摘要的聊天壳。

## 技术边界

- Swift 6、SwiftUI + AppKit，最低 macOS 14。
- 使用 PDFKit 显示 PDF，Vision 做本地 OCR，Speech 做首版语音输入，Security/Keychain 保存 OpenAI API Key。
- 若构建仍为 ad-hoc 临时签名，禁止自动读取 Keychain，改用退出即清除的会话内密钥；只有稳定签名建立后才启用长期 Keychain 存储。
- 使用 OpenAI Responses API；模型可配置。长文档建立本地带页码/章节的分块索引，问题只发送检索片段与必要上下文。AI 回答必须携带可点击的章节/页码引用。
- PDF 原件不被修改；阅读状态与批注使用应用侧边车持久化。
- Obsidian 通过用户选择 Vault 后直接协调读写 Markdown；使用应用侧状态、章节标题与内容匹配定位和去重，不得覆盖用户手写内容。
- 不引入非必要第三方依赖。密钥不得出现在源码、日志、UserDefaults 或提交记录。

## 必做交互

1. 三栏布局：左侧导航、中央 PDF、右侧 AI/笔记；左右栏可折叠和调整宽度。
2. 打开/拖放 PDF、最近文件、阅读位置恢复；单页连续、适合页面/宽度、缩放与锁定；锁定后只允许上下滚动与翻页。
3. 原生目录优先；无目录时生成可编辑候选目录。自动模式搜索全书定位目录页；指定模式跳过定位并严格读取用户给出的连续范围。AI 抄录必须与本地逐行候选合并防漏，分别处理罗马与阿拉伯页码。另提供粘贴目录文本自动解析、页码校准、任意位置插入和上下排序。
4. 左键拖选后弹出横向浮窗：三色色块直接划线，绿色下划线在选区下方打开无边框两行批注框，回车发送、Shift+回车换行；复制按钮写入系统剪贴板，普通气泡进入提问。工具栏可切换持续划线模式。
5. 文本层不足的页面后台 Vision OCR，显示进度、失败与重试；OCR 与 UI 解耦。
6. 右侧 API 对话可自由提问与语音输入，并持续显示全文加载进度。不得嵌入或自动操作第三方聊天网页。快捷问题为“联系上下文”“解释一下”“链接资源”和自定义问题；资源结果必须给出可点击链接。
7. `ljg-read` 版本化系统协议及回合状态必须嵌入每次请求：校读 OCR，拆分相连问题，区分理论来源/对象/层级/方法/证据/结论，定位前后文；首次回答生成唯一碰撞问题。读者回应后提炼其判断标准并套回原文继续压力测试，不重新开始普通问答。
8. 目录概要：每个目录条目可独立展开应用内概要，固定按问题、论证、结论、承上/启下分行并用颜色区分；每点只标一个加粗加下划线的关键短语；不写入 Obsidian。
9. Obsidian：只写入整书目录、划线/批注与 AI 对话；用内置彩色 callout 区分来源，不依赖 CSS；正文不得写入应用 HTML 注释，普通手写无背景。

## 工程质量

- 模块边界清楚：PDF、OCR、检索、AI、持久化、Obsidian、语音各自隔离，通过可测试接口协作。
- 所有耗时任务异步，主线程只更新 UI；支持取消。
- 错误信息必须说明发生了什么、数据是否安全、下一步怎么做。
- 关键逻辑写单元测试：目录推断、分块/检索、Prompt 构建、Obsidian 区块合并、响应引用解析。
- 每个里程碑都运行构建与测试；不以界面占位符冒充功能。受凭证或系统授权阻塞的真实联调要明确标注，并提供可验证的离线状态。

## 交付顺序

严格按照 `PRODUCT_SPEC.md` 的 M0-M5 进行。先交付一个能构建启动、能打开 PDF 的垂直切片，再逐步补全。每次完成后更新 README 中的已实现/待实现清单和运行方式。

## 完成定义

应用满足 `PRODUCT_SPEC.md` 的 MVP 验收标准；在可用环境中 `swift build` 与 `swift test` 通过；没有密钥泄露；用户手写 Obsidian 内容在反复同步后保持不变；至少用文本型和扫描型 PDF 各验证一次核心流程。
