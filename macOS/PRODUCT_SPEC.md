# Reading Companion for macOS - 产品与技术规格

## 1. 产品目标

Reading Companion 是一款原生 macOS PDF / EPUB / AZW3 / MOBI 深度阅读工具。它把文档阅读、可追溯的 AI 伴读和 Obsidian 长期笔记整合为一个连续工作流：打开文档 -> 自动提取/OCR/流式解析 -> 阅读与划线 -> 基于原文对话 -> 把结构化内容写回 Obsidian。

核心原则：

- 原文始终在场：AI 结论必须能回到章节与页码。
- AI 是阅读脚手架，不替代阅读；保留 `ljg-read` 的结构定位、追问、反驳和读后复盘。
- 本地优先：OCR、索引、书签、进度与笔记编排尽量在本机完成。
- 不破坏用户数据：不覆盖 PDF 原件，不覆盖 Obsidian 中的手写内容。

## 2. 已确认的默认决策

- 平台：原生 macOS App，最低 macOS 14。
- 技术：Swift 6、SwiftUI、AppKit、PDFKit、Vision、Speech、Security/Keychain。
- PDF 原件保持只读；批注保存为应用侧边车数据。
- 扫描型 PDF 使用 Apple Vision 在本地后台 OCR；已有可用文本层时跳过整页 OCR。
- AI 使用 OpenAI-compatible Responses API，支持 OpenAI 官方与 AIHUBMix 两个固定可信端点。默认模型兼顾质量与成本，并允许用户在设置中修改。
- 长文档先建立本地、带页码和章节元数据的分块索引；提问时发送焦点段、相邻页、语义邻块与必要对话历史，保证概念解释和前后文定位拥有连续证据。
- 正式签名版本的 API Key 存入 macOS Keychain，不写入项目文件、日志或 UserDefaults。
- 本地临时签名构建不访问 Keychain，避免每次换版改变代码要求并触发授权循环；改用当前用户私有的 Application Support 二进制凭据文件（目录 `700`、文件 `600`）。正式 Developer ID 签名后迁回 Keychain。
- 语音输入首版使用 macOS Speech framework；后续可选 OpenAI 实时/文件转写。
- Obsidian 由用户选择 Vault；应用通过安全作用域书签获得权限，直接协调读写 Markdown。

## 3. 功能范围

### 3.1 PDF 阅读

必须具备：

- 打开 PDF、拖放导入、最近文件。
- 自动判断文本型/扫描型/混合型 PDF，后台 OCR，并显示逐页进度、失败页和重试入口。
- 显示 PDF 自带目录；没有可信目录时先定位印刷目录页，完整 OCR 目录页，只按目录页明确列出的条目生成层级，并把印刷页码校准到 PDF 物理页。用户可从当前页指定目录总页数，也可手动添加、删除、改名、改页码与层级；手动目录须持久化。禁止扫描正文猜测标题。
- 目录点击跳转；页码输入跳转；上一页/下一页；阅读进度与上次位置恢复。
- 目录右侧提供“概要”模式。非虚构类保持按目录章节独立展开概要，按问题、论证、结论与上下章关系显示结构卡。虚构类点击“概要”后由概要栏完整覆盖目录栏，输入阅读器的起止页码生成一段简短概要；流式电子书先把排版页码映射回全文位置。每次生成都以独立板块保存页码范围与概要，新结果置顶，所有历史结果持久化并可滚动浏览。两种模式均不写入 Obsidian。
- 目录 OCR 在结构解析前统一处理兼容汉字、逐字空格、空格分隔页码、斜杠/点线/单点分隔符及竖排“目/录”页眉残片；自动识别与手动粘贴共享候选解析和页码序列校验，不允许由两个独立规则产生不同结果。
- 单页连续；适合页面、适合宽度；缩放、重置、页面锁定。锁定时持续禁止横向移动和缩放。
- 页面锁定后禁止缩放与横向移动，只允许上下滚动。
- 左侧导航分为目录、缩略图、书签、划线、搜索结果。
- 全文搜索与结果高亮；提交搜索必须保持当前阅读页不动，只有用户点击具体搜索结果时才精确跳转到该次命中的文字；同页重复词必须按结果条目分别定位，不能只跳到页面或第一个命中。
- 旋转页面。
- 密码 PDF 提示；损坏文件、OCR 不可用、磁盘空间不足等错误应可理解且可恢复。

### 3.1.1 EPUB 阅读

- 支持选择或拖放 `.epub`，解析 OPF manifest/spine、EPUB 3 navigation document 与 EPUB 2 NCX。
- EPUB、AZW3、MOBI 统一渲染为可重排正文；调整字号或阅读区宽度时文字实时换行，采用白底、系统中文无衬线字体、舒展行距和清晰标题层级。
- 自带目录映射到稳定的正文位置；无目录时复用 PDF 的目录定位和手动目录编辑、保存流程。
- 可重排正文按当前阅读区动态分页，保留明确页界与页码；滚轮/触控板达到阈值后立即按书页组翻页，使用约 150ms 动画并隔离同一次惯性手势。顶栏可选自动、单页或双页；自动模式在左右侧栏同时收起时显示双页。
- EPUB、AZW3、MOBI 的解包/解码、正文排版和全文索引均显示可见进度；电子书状态不得复用 PDF 的 OCR 文案。
- 电子书复用 PDF 的选区浮窗、划线、批注、书签、搜索、AI 提问、章节索引与 Obsidian 写入链路；划线只覆盖文字字形，不覆盖行间和两侧空白。
- 解析结果按源文件指纹缓存；源电子书修改或项目缓存被删除后重新生成，原始文件始终只读。

### 3.2 划线、批注与书签

- 鼠标拖选文本后弹出横向浮窗，依次提供三色划线、绿色下划线批注和带“AI 提问”的气泡；色块直接完成划线，批注在原文下方打开两行输入框，点击框外取消。工具栏划线按钮可切换持续划线模式。
- 三种颜色：黄、红、蓝；颜色选择记住上次设置。
- OCR 造成的中文字符间伪空格和英文单词内部异常间隔在索引、划线显示和笔记写入时自动清理，保留正常英文词间空格。
- 划线后可立即输入批注，也可稍后编辑、删除、改色。
- 支持跨行选区；一次操作保存为同一条逻辑高亮，展示和导出的原文自动去除排版换行；跨页选区拆成同组高亮。
- “所有划线”按章节/页码/时间/颜色浏览，可搜索、过滤、全选、多选、批量导出或加入笔记。
- 点击划线条目跳到原位置；点击 PDF 上的划线打开批注与 AI 快捷操作。
- 支持撤销/重做，避免误操作。
- 书签可命名、排序与删除。

### 3.3 AI 伴读

右侧为可折叠对话栏，包含：

- 自动为整本书建立索引，状态为“待处理/处理中/可提问/部分失败”。
- 自由提问与语音输入；长问题可在输入框上方的浮动窗口完整浏览和编辑；回答使用舒展行距；支持流式显示、停止生成、重试与复制。
- 每个回答显示引用的章节、页码和原文片段；点击引用跳回 PDF。
- 对话按文档保存；支持多选、全选、删除与加入笔记；侧边速览用不超过两组的关键词/关系短语概括选段内容，点击跳转；长问题浮窗只在用户点击“显示全文”后出现。
- 公开版只提供 API 伴读，不嵌入或自动操作第三方聊天网页。导入时必须选择非虚构类或虚构类，选择写入单书项目后不可更改；伴读栏标题显示“AI 伴读 · 类型”，非虚构类额外显示阅读深度。全文提取、电子书导入或 PDF OCR 的状态与进度始终可见。
- API 模型在伴读栏标题处切换，只列出当前 API Key 通过 `/models` 实际获准调用的文本模型；AIHUBMix 同时读取公开模型目录并明确显示“Key 授权数/平台总数”，避免把 Key 权限限制误认为应用删减。
- 选区触发的快捷问题优化为：
  1. **联系上下文**：这段话在回应什么问题，论证如何推进到这里？
  2. **解释一下**：解释词或句子在本文中的含义并说明关键术语。
  3. 自定义问题。
- 非虚构类把 `ljg-read` 行为以版本化协议和对话状态机写入每次 AI 请求：先校读 OCR、拆分相连问题，区分理论来源、对象、层级、方法、证据与结论，再定位前文推进/当前目标/后文任务；新问题从隐含前提、论证跳跃和最强反对中选择一个碰撞问题。读者回应后必须提炼其判断标准并套回原文检验，而非泛泛赞同。
- 虚构类不加载 `ljg-read` 框架，不追加碰撞问题，不显示快捷问题；只提供简短事实回答或适度文学分析，默认 120–300 个汉字，并保留“联系全书”。类型必须进入回答缓存键，避免两类缓存互相命中。
- 书架以封面网格显示项目，左侧固定提供全部书籍、非虚构类、虚构类及自建文件夹；支持多选后批量删除、批量加入/移出文件夹，或统一修改为非虚构类/虚构类。分类变更同时更新书籍的持久化状态与 AI 伴读模式。同一本书可同时属于多个文件夹，并出现在当前书籍类型分类中。每本新书首次加入时必须选择类型；升级到该规则前已加入的书籍一次性显示为“未分类”，再次打开时强制选择，也可从批量管理直接分类。文件夹是应用内元数据，不移动或修改原始书籍。
- 书架优先显示 EPUB 内嵌封面；缺少封面或旧项目无封面时生成稳定的书名封面并在后台补齐，不改变书籍排序。
- 已生成的封面使用立即解码的内存图像显示，打开书籍时不会重复覆盖当前封面；进入文件夹时封面网格保持稳定宽度。批量整理会即时更新界面并进入目标文件夹。
- 虚构类导航栏增加“人物”：左侧保持紧凑的人物索引，右侧人物管理栏暂时代替 AI 对话；支持按“人物：身份，关系等信息”逐行批量识别或逐个添加，并可直接修改、删除。每个人物使用自动生成且不重复的独立颜色，同一人物所有名字在全文同色高亮，人物第一次出现额外加粗。展开人物后最多列出 11 次出现，以离当前页最近的一次为中心，通常前后各 5 次；任一侧不足时从另一侧补足，总数不足 11 次则全部列出。每条显示其全文序号和页码，并支持上一次/下一次精确跳转。
- 人物姓名高亮按书默认开启，可在人物管理栏关闭；流式阅读只更新绘制层，不改写正文 DOM、分页或当前位置。
- 打开人物导航默认只显示左侧人物索引，右侧继续显示 AI 伴读；点击人物索引右上角“管理”后才用人物管理面板替换右侧栏。普通划线与人物高亮共享紧贴字形的矩形算法，不覆盖段落空白，且仅绘制当前单页或双页范围。
- 隐私控制：发送前明确展示将上传的内容类型；支持“只发送检索片段”和“允许上传 PDF”两种策略，默认前者。
- 成本控制：显示本次估算/实际用量；可限制最大上下文和每月预算提醒。

### 3.4 Obsidian 笔记

- 设置中选择 Vault、笔记目录与命名模板。
- “生成全书骨架”：创建一本书对应的 Markdown 索引，按章节生成标题层级和稳定章节 ID。
- 非虚构类章节概要、虚构类页码范围概要与下层框架均不写入 Obsidian；目录底部只保留“添加目录”一个入口。
- 工具栏“笔记”集中 Vault、目录、打开笔记、划线/批注和 AI 对话。
- 笔记中心支持“全选未加入”；应用侧写入状态与内容匹配共同阻止重复记录。
- 划线浏览器支持多选，将选中的划线与批注加入相应章节。
- AI 对话支持多选；写入时以提问发生页而非回答的检索证据页确定章节，多章内容分章写入。可选择保留原始问答，或压缩为有标题、结论、证据、保留分歧与来源页码的讨论笔记，并可设为在 Obsidian 中默认折叠。
- 使用 Obsidian callout 区分来源：
  - 章节骨架：标准 Markdown 标题层级。
  - 划线：背景色跟随黄、红、蓝原始划线颜色。
  - 独立批注：绿色 `annotation` callout；划线附言：紧贴划线下方的浅蓝色 `comment` callout。
  - AI 讨论：使用独立的 `question` callout。
  - 用户手写：普通 Markdown，不加背景。
- 颜色使用 Obsidian 内置 callout，无需用户启用 CSS snippet。
- 笔记正文不写入 Reading Companion HTML 注释；使用章节标题定位、应用侧状态和内容匹配避免重复，不覆盖用户手写内容。旧标记在下次写入时自动清理。
- 用文件协调与修改时间检测避免同时编辑冲突；冲突时保留双方内容并提示合并。
- 提供“在 Obsidian 中打开当前笔记”，使用 `obsidian://` URL scheme。

## 4. 数据与安全

- 文档身份使用内容哈希，不依赖易变化的文件路径。
- 本地保存：阅读位置、目录修订、书签、划线、批注、OCR 文本、索引元数据、对话与 Obsidian 映射。
- 所有保存均原子化；保留可恢复备份。
- 正式签名版 API Key 存 Keychain；临时签名版存当前用户私有凭据文件。日志自动脱敏；不记录完整 PDF 文本或用户密钥。
- 删除文档时分别询问是否删除本地索引、对话和 Obsidian 笔记，不删除 PDF 原件。
- 明确说明所选 AI 服务商的上传策略、保留策略和费用由用户账户承担。

## 5. 首版（MVP）验收标准

1. App 能在 macOS 14+ 构建并启动，拖入或选择一个 PDF 后可显示和翻页。
2. 支持单页连续、适合页面、缩放与锁定；锁定时禁止横向移动和缩放，只允许上下滚动。
3. 能显示原生目录；无可信目录时定位印刷目录页，仅按其完整信息生成可跳转目录，并正确处理印刷页码与 PDF 物理页码偏移。
4. 对扫描页能启动 Vision OCR 并产生带页码文本；UI 不阻塞。
5. 能创建三色高亮、批注、书签，并在侧栏浏览后跳回页面。
6. 能对文档与选区发起 AI 问答；无 Key 时给出明确设置入口；回答保留页码引用。
7. 能连接 Obsidian Vault、生成章节骨架，并把高亮/批注/AI 摘要写入正确章节且不覆盖手写内容。
8. 关闭重开后恢复文档位置和本地批注。

## 6. 分期

- M0：可构建的原生应用骨架、PDF 打开/显示、三栏布局、设置与数据模型。
- M1：显示模式、目录/书签/搜索、高亮/批注、持久化。
- M2：Vision OCR、目录推断、全文本地索引。
- M3：Responses API、引用跳转、选区快捷问题、语音输入。
- M4：Obsidian 骨架、内置彩色 callout 分类写入与冲突保护。
- M5：性能、可访问性、签名与分发。

## 7. 当前环境缺口

- 已有：macOS 15.7、Apple Silicon、Swift 6.1、Command Line Tools、Obsidian。
- 缺少完整 Xcode；命令行可先构建 Swift Package，但要做签名、权限说明、沙盒调试、Archive/Notarization 与正式 `.app` 分发，必须安装完整 Xcode 并在 `xcode-select` 中启用。
- 当前没有 XcodeGen/Tuist/Homebrew/Tesseract；本方案首版不依赖它们。OCR 使用系统 Vision，避免外部 OCR 安装。
- 需要用户提供受支持平台的 API Key 才能联调真实 AI；应用自动识别 OpenAI、AIHUBMix、Anthropic、Google Gemini、DeepSeek 或 OpenRouter，没有 Key 时使用清晰的未配置状态，不伪造响应。
- 需要用户在首次运行时授权目标 Obsidian Vault、麦克风与语音识别权限。
- 正式分发还需要 Apple Developer 账号、签名证书、公证与隐私说明；本地自用构建不要求账号。
